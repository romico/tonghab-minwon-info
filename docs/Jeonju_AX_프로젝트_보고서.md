## 1. 요약

Jeonju AX 통합민원정보 프로젝트는 생활민원 데이터를 한 곳에서 관리하고, 부서별 현황·총괄표·일일보고·대시보드 등 반복적으로 작성하는 보고를 같은 원천 데이터에서 산출하도록 설계한 내부 업무지원 서비스입니다. 중심 원칙은 **“입력은 한 번, 집계는 같은 기준으로, 보고는 확인 가능하게”**입니다.

현재 저장소에는 관리대장, 기간·보고일 기준 집계, HWPX 민원카드 가져오기와 담당자 검수, Excel 출력, 보고 스냅샷, 인증·감사 기능, 포터블 배포 및 데이터 아카이브·복원 기능이 구현되어 있습니다. 운영 형태는 로컬 우선이며, 단일 PC·단일 관리자 중심의 사용을 기준으로 합니다.[1]

따라서 이 프로젝트를 시민이 새 민원을 접수하는 앱이나 생성형 AI 민원 자동처리 시스템으로 소개해서는 안 됩니다. 특히 국토교통부의 도로이용불편 척척해결서비스는 시민이 도로 불편을 신고하고 담당 도로관리기관의 이관·처리 결과를 확인하는 기존 채널입니다. 전주시 통합민원정보는 내부 민원관리·집계·보고 도구로 역할이 다르며, 두 시스템의 자동 연계는 현재 확인된 기능이 아닙니다.[2][3]

다음 단계의 초점은 기능을 무조건 확장하는 것이 아니라 **Excel 공유 시 개인정보 통제, 백업·복구의 실증, 집계 규칙 검증, 문서와 배포 버전 정합성**을 먼저 정비하는 것입니다. 효과를 설명할 때도 측정 전의 시간 절감이나 오류 감소를 성과 수치로 말하지 않고, 현장 시범운영을 통해 확인해야 합니다.

## 2. 추진 배경과 해결하려는 업무 문제

생활민원 업무에서는 접수 내용을 관리대장에 정리한 뒤 부서별 현황, 총괄 현황, 일일보고 등 여러 자료로 다시 옮겨 적거나 집계하는 일이 발생할 수 있습니다. 여러 파일과 시트에서 각각 수식과 복사본을 관리하면 수치가 달라져도 원인을 찾기 어렵고, 통보일·보고일 같은 기준을 잘못 적용할 가능성도 있습니다.

이 프로젝트는 이러한 문제를 업무 흐름과 데이터 구조의 개선으로 다룹니다.

| 현장 업무의 문제 | 프로젝트의 대응 방향 |
|---|---|
| 보고 양식마다 자료와 수식이 분산됨 | 관리대장을 단일 입력 원천으로 두고 보고 화면을 같은 기준에서 집계 |
| 보고 기준일과 대상 기간이 혼동될 수 있음 | 보고일과 통보일 기간을 구분해 보여주고, 날짜별 보고 스냅샷을 제공 |
| 민원카드·사진을 다시 입력해야 함 | HWPX에서 초안을 가져오고 담당자가 검수한 다음 등록 |
| 보고 형식이 여러 개라 반복 정리가 필요함 | 부서별·총괄·일일 현황 및 Excel 출력 흐름을 통합 |
| PC마다 실행 환경이 다를 수 있음 | 런타임을 포함한 포터블 배포와 로컬 실행 방식을 채택 |
| 개인정보가 화면·파일 공유 과정에서 노출될 수 있음 | 저장 암호화와 화면 마스킹 등 보호 기능을 제공하되, Excel 내보내기 통제는 보완 과제로 관리 |

## 3. 프로젝트 목표와 범위

### 3.1 목표

1. 민원 원천을 하나의 관리대장에서 관리하고 관련 현황·보고서 간 데이터 기준을 일관되게 유지합니다.
2. 보고일·통보일 기간·처리 상태를 분명히 해 사용자가 어떤 기준의 숫자인지 확인할 수 있도록 합니다.
3. HWPX 자료의 반복 입력을 줄이되, 자동 추출 결과는 담당자가 검수하도록 합니다.
4. 보고 시점의 주요 집계 결과를 스냅샷으로 남겨 사후 비교를 돕습니다.
5. 로컬 단독 운영을 유지하면서 데이터 이전·아카이브·복구와 개인정보 보호를 단계적으로 개선합니다.

### 3.2 현재 범위와 비목표

현재 확인되는 서비스는 민원 담당자와 보고 담당자가 사용하는 내부 웹앱입니다. 시민이 직접 민원을 신고하는 공개 접수 앱, 국토교통부 척척해결서비스와의 자동 연계, 클라우드 다중기관 서비스, 여러 PC의 실시간 동시 편집 또는 부서별 권한 분리는 현재 범위로 확인되지 않습니다.

HWPX 가져오기는 정보 추출을 돕는 기능이지 민원 내용을 자동 판단하거나 처리 상태를 무인 확정하는 AI 기능이 아닙니다. 따라서 발표 시 프로젝트의 AX 방향은 **데이터와 업무 흐름을 정돈해 향후 고도화 기반을 마련하는 것**으로 설명하는 편이 정확합니다.

## 4. 서비스 구성과 업무 흐름

```text
민원 자료 확보
  ├─ 담당자 직접 입력
  └─ HWPX 민원카드 가져오기 → 초안 검수·보완
                ↓
        관리대장(단일 입력 원천)
                ↓
      기간·보고일 기준으로 집계
         ├─ 대시보드
         ├─ 부서별 현황
         ├─ 총괄표
         ├─ 일일보고
         └─ Excel 출력 및 보고 스냅샷
```

관리대장은 입력·수정의 기준 원천이고, 여러 보고 화면은 관리대장 데이터를 이용해 계산하는 구조입니다. 보고 스냅샷은 보고일·기간, 대상 민원 식별자, 주요 KPI와 일일 집계 등을 보존해 주요 숫자를 확인하는 데 쓰입니다. 이는 생성된 Excel 원본 파일 전체나 민원 본문 전체를 보관하는 문서기록관리 기능과는 구별됩니다.[1][4]

### 구현·성과 표현의 주의사항

저장소의 최신 `package.json` 버전은 0.1.19이나 README에는 0.1.18, 기존 기획·현황 보고서에는 0.1.4가 표시되어 있습니다. 이는 저장소와 문서 간 정합성 문제를 보여주는 것이므로, 외부 발표 전에 실제 배포본 버전과 문서 기준일을 확인하고 일치시켜야 합니다.[1][5]

또한 통합 Excel의 마스킹 동작은 안전한 기본값이라고 보장하기 어렵고, 내보내기 이벤트별 감사도 현재 구현 근거가 확인되지 않았습니다. 화면에서 개인정보를 가리는 것과 생성된 파일을 안전하게 만드는 것은 별도 통제입니다. 이 항목은 대외 발표에서 감추기보다 “공유 단계에서 보완 중인 운영 과제”로 설명하고, 실제 배포 전에 안전한 설정과 확인 절차를 검증해야 합니다.[4][6]

저장 암호화 역시 모든 민원 필드가 암호화된다는 뜻은 아닙니다. 프로젝트 보안 정책은 성명·연락처·사진 등 일부 항목을 암호화 대상으로 설명하며, 민원 내용·위치·비고 등 자유 입력 필드에는 개인정보가 포함될 수 있습니다. 실제 적용기관에서는 입력 지침과 파일 반출·접근통제를 함께 검토해야 합니다.[7]

## 6. 국토교통부 척척해결서비스와의 관계

국토교통부의 도로이용불편 척척해결서비스 앱은 도로 이용 시민이 포트홀, 낙석, 시설물 파손 등 불편사항을 사진·위치정보와 함께 신고하고 처리 결과를 확인하는 기존 시민 접점입니다. 전주시 공식 안내는 등록된 신고가 담당기관에 전달되고, 접수·관계기관 이관 및 처리 결과를 앱에서 확인할 수 있다고 설명합니다.[2][3]

| 구분 | 척척해결서비스 앱·업무 흐름 | 전주시 통합민원정보 |
|---|---|---|
| 1차 사용자 | 시민 신고자와 담당 도로관리기관 | 전주시 내부 민원·보고 담당자 |
| 목적 | 도로 이용 불편 신고, 담당기관 전달, 처리 결과 안내 | 생활민원 관리대장, 내부 업무현황과 보고 집계 |
| 데이터 단위 | 개별 도로 불편 신고와 처리 경과 | 내부 관리가 필요한 민원 원천과 파생 보고 |
| 시민 신고 기능 | 제공 | 현재 확인된 범위에는 없음 |
| 자동 연계 | 척척 서비스 내부 신고·이관·결과 확인 흐름은 공개 안내에서 설명 | 척척 서비스와의 API 연계·동기화 기능은 저장소에서 확인되지 않음 |

따라서 통합민원정보를 “국토교통부 앱의 대체재”나 “새로운 도로 민원 접수 앱”이라고 소개하지 않습니다. 시민 접수는 기존 채널을 우선 존중하고, 시 내부에서 추가적인 업무추적·통계·보고가 필요한지 확인한 뒤 필요한 최소 범위에서 보완하는 방향이 적절합니다. 접수번호·상태·사진 등을 실제로 주고받는 절차나 API가 있는지는 별도 기관 협의와 기술 확인이 선행되어야 합니다.[2][3][8]

## 7. 기대 효과와 검증 방법

현재 자료에는 업무시간 단축률, 오류 감소율, 실제 사용자 수, 처리기간 개선 등 확정 가능한 운영 실측치가 제시되어 있지 않습니다. 따라서 지금 단계의 보고는 **구현된 기능과 기대 효과**를 구분해야 합니다.

| 측정 지표 | 정의 예시 | 측정 방식 |
|---|---|---|
| 민원 등록 소요시간 | 자료 확인 시작부터 관리대장 저장까지 걸린 시간 | 업무유형·자료유형을 나눠 시범운영 전후 표본 비교 |

| 재작업률 | 보고서 생성 후 숫자·기준 수정이 필요한 보고 비율 | 수정 사유와 건수를 익명·집계 방식으로 기록 |
| 기준 오류율 | 보고일·기간·상태 기준을 수정해야 했던 건 비율 | 검토자가 정의한 오류 유형으로 분류 |
| 집계 일치율 | 같은 원천과 기준에서 시스템 집계와 검증 대조값이 일치한 비율 | 대표 사례와 경계값을 정해 표본 또는 자동 테스트 수행 |
| 복구 시험 성공률 | 정해진 백업본으로 별도 환경에서 복구가 완료된 비율 | 주기적 복원 리허설과 결과 기록 |
| 마스킹 예외 비율 | 원문 포함 Excel이 생성된 비중 | 다운로드 보호·감사 기능 구현 후 최소한의 이벤트 집계 |

측정 시에는 실제 민원인 정보를 지표용으로 추가 수집하지 않고, 표본·집계 기준과 측정기간을 함께 공개해야 합니다. 전후 비교에서는 계절성, 업무량, 담당자 숙련도와 양식 변경 등 영향을 구분해야 하며, 충분한 자료가 없으면 정량 효과 대신 현장 인터뷰와 시나리오 검증 결과를 제시합니다.

### 8.2 권장 단계

**1단계 — 기준과 품질 정비:** 보고 기준과 용어를 통일하고, 집계 테스트 및 버전 정합성을 확보합니다. 도입 전후 성과를 측정할 업무 기준선도 정합니다.

**2단계 — 안전한 공유·복구:** Excel 마스킹 기본값과 원문 예외 절차, 내려받기 이력, 백업·복원 절차를 구현·시험합니다. 운영 데이터가 없는 별도 환경에서 복구 리허설을 수행합니다.

**3단계 — 현장 시범운영:** 업무 담당자와 관리자에게 사용·보안 절차를 안내하고, 소규모 범위에서 사용성·집계 일치·복구 가능성을 점검합니다. 시범운영의 기간, 대상 업무, 측정 지표와 중단 조건을 사전에 합의합니다.

**4단계 — 연계·협업 검토:** 다중 사용자, 사내망 접근, 외부 시스템 연계는 시범운영 결과와 보안 검토를 바탕으로 판단합니다. 특히 척척해결서비스 연계는 API 유무와 기관 간 데이터 제공 근거가 확인된 후에만 추진합니다.

## 9. 다른 지자체에 적용할 때의 교훈

이 프로젝트에서 다른 지자체가 우선 참고할 것은 제품 화면을 그대로 복제하는 일이 아니라 업무 기준을 정리하는 순서입니다.

- 어떤 원장이 실제 원천인지, 보고마다 별도 복사본을 관리하는지 먼저 조사합니다.
- 접수일·통보일·보고일, 처리완료 기준과 집계 경계를 업무 담당자와 합의합니다.
- 자동 추출·집계가 담당자 검수를 대체하지 않도록 책임 지점을 설계합니다.
- 시민 신고 채널과 내부 업무관리 도구를 분리하고, 이미 있는 중앙·광역 서비스를 새 앱으로 중복 구축하지 않습니다.
- 개인정보 보호를 화면뿐 아니라 Excel·사진·백업·공유 경로까지 포함해 검토합니다.
- 시범 적용으로 시간·재작업·집계 일치·복구 성공을 측정한 뒤 확장 여부를 판단합니다.

민원 분류, 부서 조직, 보고 양식, 기록관리 규정은 기관마다 다릅니다. 따라서 프로젝트의 관리대장 단일 원천화와 검증 접근은 참고하되, 시스템과 운영절차는 해당 지자체의 기준에 맞춰 다시 설계해야 합니다.

## 10. 보고 및 발표자료의 권장 메시지

### 보고서의 핵심 결론

> “Jeonju AX 통합민원정보는 시민 민원 접수 채널을 새로 만드는 사업이 아니라, 생활민원 관리와 반복 보고를 공통 데이터 기준으로 정리하는 내부 업무지원 프로젝트다. 현재 구현을 바탕으로 개인정보가 포함된 파일 공유와 데이터 복구를 검증하고, 실제 효과를 측정한 뒤에만 협업·기관 연계를 확장한다.”

### 발표자료 구성안

1. **현장의 문제:** 관리대장과 보고 양식이 분산되면 반복 입력·집계·대조가 생깁니다.
2. **프로젝트의 목표:** 민원 원천과 보고 기준을 정리해 같은 데이터가 여러 보고로 이어지게 합니다.
3. **업무 흐름:** 입력·HWPX 검수에서 관리대장, 현황·보고서까지 한 흐름으로 보여줍니다.
4. **기존 서비스와의 관계:** 척척해결서비스는 시민 도로 신고·결과 확인, 통합민원정보는 내부 관리·보고라는 경계를 제시합니다.
5. **현재 구현:** 관리대장 단일 원천, 자동 집계, 보고 스냅샷, 포터블 운영을 설명합니다.
6. **정직하게 말할 한계:** 실측 효과 부족, Excel 공유 보호와 복구 검증 과제를 밝힙니다.
7. **다음 단계:** 안전한 공유·복구, 지표를 둔 현장 시범, 이후 협업·연계 검토 순서를 제안합니다.
8. **요청 사항:** 시범 적용 업무·담당자·측정 지표·보안 검토 주체를 합의합니다.

발표 데모는 실제 민원 데이터가 아닌 합성·비식별 예시 자료로 진행합니다. “AI가 민원을 자동 처리한다”, “국토교통부 앱과 연동된다”, “업무시간을 특정 비율로 줄였다”는 표현은 각각 현재 구현·연계·실측 근거를 확인하기 전까지 사용하지 않습니다.

## 결론

Jeonju AX 통합민원정보의 현재 가치는 생활민원 데이터 관리와 보고를 하나의 업무 흐름으로 연결하려는 구조에 있습니다. 다른 지자체에 설명할 때는 이를 완성된 도시 전체 AX 플랫폼이나 시민 신고 앱으로 포장하지 말고, **현장 업무의 기준 데이터를 정리하고 반복 보고를 개선하는 단계적 프로젝트**로 소개해야 합니다.

우선순위는 기능 확장보다 공유 파일의 개인정보 보호, 검증 가능한 백업·복구, 집계 기준 품질, 효과 측정입니다. 국토교통부 척척해결서비스와는 시민 신고 창구를 중복 구축하지 않는다는 원칙 아래, 공식 접수·처리 흐름과 시 내부 업무 관리가 실제로 어디서 만나는지를 확인한 뒤 상호보완 방식을 설계하는 것이 바람직합니다.
