# 포터블 ↔ 모바일 동기화 · QR 페어링

> 상위: [README.md](./README.md) · 상태: 설계 검토 (미구현)  
> 질문: 포터블 앱과 모바일을 QR로 “통신”할 수 있는가?

## 1. 결론

| QR로 할 일 | 가능? | 설명 |
|---|---|---|
| **페어링** (주소·토큰·만료 시각 전달) | ✅ 권장 | 폰이 포터블 서버에 HTTP로 붙기 위한 부트스트랩 |
| **민원·사진·DB 동기화 본체** | ❌ 비권장 | QR 용량·촬영 오류로 실데이터 전송에 부적합 |
| 민원 1건 ID만 공유 | △ 가능 | 짧은 deep link용. 본문은 여전히 API |

실제 동기화는 항상 **같은 Wi‑Fi/사내망 HTTP(S) API**로 한다. QR은 “어디에, 어떤 권한으로 붙을지”만 넘긴다.

```text
[포터블 PC]                         [모바일]
 서버 기동 (사내 IP:8787)
 페어링 토큰 발급
 QR 표시 ────────────────스캔───►  baseUrl + token 저장
        ◄──────── HTTP API ──────  조회·촬영 업로드·큐 flush
```

이미 본제품에 `qrcode` 패키지(TOTP 설정용)가 있으므로, **페어링 QR UI 재사용 비용은 낮다.**

## 2. 왜 데이터는 QR로 안 되나

| 제약 | 의미 |
|---|---|
| 용량 | 실용 QR은 수백~2KB 수준. JPEG·HWPX·민원 JSON 불가 |
| 오류 | 인쇄·화면 반사·해상도에 민감 |
| 양방향 | QR은 본질적으로 PC→폰 **일회성 푸시**. 업로드·ACK에 부적합 |
| 보안 | 화면 노출 = 토큰 노출 → **짧은 TTL·1회용** 필수 |

## 3. 권장 페어링 페이로드

QR에 넣는 JSON(또는 URL) 예:

```json
{
  "v": 1,
  "baseUrl": "http://192.168.10.23:8787",
  "pairToken": "…",
  "exp": 1726550000,
  "deviceHint": "portable-desk-1"
}
```

또는 단일 URL:

```text
tm://pair?v=1&u=http%3A%2F%2F192.168.10.23%3A8787&t=…&exp=…
```

모바일 동작:

1. 스캔 → `baseUrl` 저장  
2. `POST /api/pair/redeem` + `pairToken` → 세션/기기 토큰 발급  
3. 이후 API는 기기 토큰으로 호출  
4. `exp` 초과·재사용 시 거절

## 4. 포터블 쪽 선행 조건

현재 기본 `HOST=127.0.0.1`이면 **폰에서 접속 불가**. 페어링 모드일 때만:

| 항목 | 권장 |
|---|---|
| 바인딩 | LAN IP 또는 `0.0.0.0` (설정/메뉴로 명시적 전환) |
| 표시 | QR에 찍힌 IP가 실제 리스닝 주소와 일치 |
| 방화벽 | macOS/Windows에서 포트 허용 안내 |
| 종료 | 페어링 창 닫거나 TTL 만료 시 토큰 무효 |

동일 Wi‑Fi가 아니면 QR만으로는 통신되지 않는다 (핫스팟·VPN은 별도 시나리오).

## 5. 동기화 패턴과의 관계

| 단계 | 채널 |
|---|---|
| 최초 연결 | QR 페어링 |
| 온라인 작업 | HTTP API (민원 조회, `photos` append) |
| 오프라인 촬영 | 모바일 pending 큐 |
| 복귀 후 | 저장된 `baseUrl`로 큐 flush (QR 재스캔 불필요, 토큰 유효 시) |
| 토큰 만료·PC IP 변경 | QR 재스캔 |

PC가 sleep/이동으로 IP가 바뀌면 페어링을 다시 한다. mDNS(`tonghab.local`)는 선택 개선.

## 6. 대안 비교

| 방식 | 장점 | 단점 |
|---|---|---|
| **QR 페어링 + HTTP** | UX 좋음, 용량 무관, 본제품과 맞음 | 동일 네트워크 필요 |
| IP·포트 수동 입력 | 구현 단순 | 현장 오류 많음 |
| USB/케이블 파일보내기 | 망 불필요 | 사진 실시간 처리에 부적합 |
| 클라우드 중계 | 망 달라도 됨 | 본제품·비목표(클라우드)와 충돌 |
| QR에 민원 요약만 | 인쇄물·공유용 | 동기화 대체 불가 |

## 7. 보안 체크리스트

- [ ] pairToken 짧은 TTL (예: 2–5분) · 1회용  
- [ ] 페어링 성공 감사 로그  
- [ ] 페어링 모드 ON일 때만 LAN 바인딩 (기본은 localhost 유지 가능)  
- [ ] 선택: PIN 4자리 추가 확인 (옆자리 스캔 방지)  
- [ ] HTTPS 또는 사내 VPN (평문 HTTP는 사내망 한정·위험 고지)

## 8. 본제품 영향 경계

- 설정 화면 「모바일 연결(QR)」은 **feature / 별도 메뉴**로 두고, 기본 포터블 동작은 localhost 유지.  
- 상세 구현·패키지는 `docs/mobile-intranet/` 트랙. 본제품 PRD에 기능을 섞지 않는다.
