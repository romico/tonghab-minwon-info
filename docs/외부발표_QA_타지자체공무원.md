# Jeonju AX 통합민원정보 — 예상 Q&A

> 용도: 타 지자체 공무원 대상 대외 발표·질의응답 리허설
기준: 저장소 코드·문서 확인 기준 2026-10-22
주의: 이 문서는 현재 확인 가능한 구현을 바탕으로 작성한 발표 초안입니다. 실제 운영 여부, 적용기관, 효과 수치, 보안 점검·승인 이력은 발표 전에 별도 확인해야 합니다.

## 답변 원칙

- 질문에 먼저 직접 답하고, 근거와 한계를 짧게 덧붙입니다.

- 구현된 기능, 운영 검증이 필요한 사항, 향후 계획을 구분합니다.

- 확인하지 않은 도입 실적·효과 수치·인증·법규 준수 여부는 주장하지 않습니다.

- 답을 모르면 추정하지 말고 “현재 확인된 자료로는 답을 단정하기 어렵고, 확인 후 공유하겠다”고 답합니다.

- 발표 자료에는 실제 민원인 정보가 포함된 화면·파일을 사용하지 않습니다.

## 1. 성과와 AX의 실체

### Q1. 이름에 AX가 들어가는데, 실제로 어떤 AI를 쓰고 있습니까?

**모범 답변**
“현재 통합민원정보의 핵심은 생성형 AI가 민원을 판단하거나 답변하는 것이 아니라, 민원 데이터를 한 곳에서 관리하고 같은 기준으로 여러 보고를 만드는 업무 자동화입니다. HWPX 민원카드에서 일부 항목을 추출하는 기능도 있지만, 자동 판정으로 확정하는 방식이 아니라 담당자가 확인·수정한 뒤 등록합니다. 저희는 이를 향후 AX 고도화의 기반으로 보고 있으며, AI 적용 여부와 범위는 데이터 품질·책임·보안 조건을 검토해 별도로 판단해야 합니다.”

**답변 포인트:** “AI가 자동 분류한다”, “민원을 자동 처리한다”라고 말하지 않습니다. 현재 구현된 데이터 통합·집계와 향후 AI 검토를 분리합니다.

### Q2. 실제로 업무 시간이 얼마나 줄었고, 오류가 얼마나 감소했습니까?

**모범 답변**
“현재 확인 가능한 자료만으로 시간 단축률이나 오류 감소율을 확정 수치로 말씀드리지는 않겠습니다. 시스템은 반복 집계와 보고서별 중복 관리를 줄이도록 설계됐지만, 효과 크기는 현장 업무를 기준으로 측정해야 합니다. 도입 전후 민원 등록시간, 보고서 작성·수정시간, 숫자 재확인 횟수와 기준 오류율을 같은 정의로 비교하는 것이 적절합니다.”

**답변 포인트:** 측정하지 않은 수치를 만들어내지 않습니다. 수치 질문에는 측정 설계와 다음 검증 계획으로 답합니다.

### Q3. 자동 집계가 기존 Excel보다 정확하다는 근거가 있습니까?

**모범 답변**
“구조적인 근거는 관리대장을 단일 입력 원천으로 두고 여러 보고 화면이 같은 집계 규칙을 사용한다는 점입니다. 그렇다고 원천 데이터 입력 오류나 집계 규칙의 오류까지 자동으로 사라지는 것은 아닙니다. 그래서 날짜 경계, 처리 상태, 부서·분야 분류 같은 대표 사례를 자동 검증하고, 표본 대조와 담당자 검토를 함께 운영해야 합니다. 정확도 개선의 정도는 실제 업무 자료로 검증해 공개하겠습니다.”

**답변 포인트:** “항상 정확하다”, “오류가 없다”고 보장하지 않습니다. 단일 원천은 불일치 원인을 줄이는 구조이지 데이터 품질 보증 그 자체는 아닙니다.

### Q4. 기존 민원업무 시스템을 대체하는 겁니까, 보완하는 겁니까?

**모범 답변**
“현재 설명드리는 범위는 생활민원 원천 관리와 현황·보고 업무를 지원하는 것입니다. 기존 행정 시스템이나 공식 접수 채널을 대체하거나 직접 연계한다고 말씀드릴 근거는 없습니다. 기관별 기존 시스템의 역할을 먼저 확인하고, 중복 입력·보고 기준 문제를 어디서 개선할 수 있는지 별도로 판단해야 합니다.”

**답변 포인트:** 기존 시스템과의 연계가 확인되지 않았다면 “연계되어 있다”고 말하지 않습니다.

## 2. 데이터와 보고 신뢰성

### Q5. 보고서 숫자가 달라졌을 때 어떤 기준으로 원인을 추적할 수 있습니까?

**모범 답변**
“보고 결과를 설명하려면 보고일, 통보일 기간, 대상 건수, 사용한 집계 규칙이 함께 명확해야 합니다. 현재 화면과 보고 스냅샷은 보고일·기간 및 집계 결과를 확인하는 기반을 제공합니다. 다만 원천 데이터의 수정 이력, 스냅샷의 대상 식별 정보, Excel 파일 생성 이력은 각각 역할이 다르므로 완전한 감사·재현 체계라고 과장하지 않고, 어떤 범위가 저장되는지 구분해 설명하겠습니다.”

**답변 포인트:** “원인을 모두 자동 추적한다”고 약속하지 않습니다. 집계 기준의 확인과 원천 변경의 추적을 구별합니다.

### Q6. 과거에 확정한 보고서를 나중에 완전히 똑같이 재생성할 수 있습니까?

**모범 답변**
“현재 스냅샷은 보고일별 KPI·일일 집계, 대상 민원 ID 목록과 기간 등 메타데이터를 보존해 확정 당시 주요 숫자를 확인하고 비교하는 데 쓰입니다. 다만 생성된 Excel 파일 자체나 민원 전체 내용을 그대로 복제해 보존하는 기능과는 다릅니다. 따라서 ‘주요 집계 결과를 보존한다’고 설명하는 것이 정확하고, 원본 파일까지 장기 보존해야 한다면 별도 기록관리·보존 정책과 설계가 필요합니다.”

**답변 포인트:** 스냅샷을 완전한 문서 원본 보관 또는 전체 업무기록 재현으로 표현하지 않습니다.

### Q7. 스냅샷을 다시 확정하면 과거 값이 덮어써지지 않습니까?

**모범 답변**
“같은 보고일을 다시 확정할 때 새 이력을 추가하는 구조이며, 이전 스냅샷도 조회할 수 있도록 되어 있습니다. 다만 재확정 사유를 의무화하거나 확정본 변경을 조직의 승인 절차와 연결하는 것은 별도의 업무·통제 설계가 필요합니다. 발표에서는 ‘재확정 이력이 남는다’고 설명하고, 기관별 결재·기록관리 절차를 대체한다고 말하지 않겠습니다.”

### Q8. Excel을 내려받으면 개인정보는 기본적으로 가려집니까?

**모범 답변**
“화면의 기본 마스킹과 Excel 파일의 보호는 별개입니다. 현재 저장소의 통합 Excel 생성 코드는 마스킹 기본값이 꺼져 있고 사진 포함 기본값은 켜져 있어, 통합 파일이 기본적으로 안전하게 마스킹된다고 말씀드릴 수 없습니다. 내려받기 단계의 기본 마스킹, 원문 선택 시 경고, 생성 이력 기록을 먼저 강화·검증한 뒤 외부 공유나 확대 적용을 논의하는 것이 맞습니다.”

**답변 포인트:** 이 질문은 가장 민감한 사실 확인 항목입니다. “화면에서 가리므로 Excel도 안전하다”고 답하지 않습니다. 실제 배포본에서 설정을 변경했는지 발표 전에 다시 확인합니다.

## 3. 개인정보·보안·운영 책임

### Q9. 민원 데이터는 전부 암호화되어 저장됩니까?

**모범 답변**
“전부라고 말할 수는 없습니다. 현재 정책과 구현 설명상 성명·연락처·사진 등 일부 개인정보 항목은 저장 암호화 대상이고, 선택적으로 2단계 인증도 사용할 수 있습니다. 반면 민원 내용·위치·비고 같은 자유 입력 필드는 집계·검색을 위해 평문으로 남을 수 있으며, 그 안에 개인정보가 적히지 않도록 운영 안내가 필요합니다. 따라서 ‘모든 민원 정보가 암호화된다’고 표현하지 않고 보호 범위와 잔여 위험을 함께 설명하겠습니다.”

**답변 포인트:** 암호화 대상과 예외를 구별합니다. 화면 마스킹·저장 암호화·Excel 통제를 하나의 기능처럼 묶지 않습니다.

### Q10. 지자체의 정보보호·개인정보 기준이나 보안 인증을 충족했습니까?

**모범 답변**
“현재 자료만으로 특정 기관의 보안성 검토, 개인정보 영향 검토, 인증 또는 법적 적합성 승인을 완료했다고 말씀드릴 수 없습니다. 실제 업무 적용 전에는 해당 기관의 정보보호·개인정보 담당 부서가 데이터 항목, 설치·접근 환경, 보존·파기, 백업·반출 절차를 검토해야 합니다. 이 시스템의 기능 설명은 기관별 보안 심의나 법적 검토를 대체하지 않습니다.”

**답변 포인트:** 확인되지 않은 인증·법규 준수 주장을 하지 않습니다. 운영기관의 책임과 시스템 기능을 구분합니다.

### Q11. 로컬 PC에서 운영하면 네트워크 보안은 걱정하지 않아도 됩니까?

**모범 답변**
“현재 기본 설계는 해당 PC 내부에서 사용하는 로컬 우선 방식으로, 여러 PC가 동시에 접속하는 중앙 서비스와는 다릅니다. 로컬 운영은 외부 공개를 줄이는 장점이 있지만 PC 분실, 계정 관리, 운영체제 보안, 백업 파일 반출 같은 위험이 없어지는 것은 아닙니다. 사내망 접속이나 원격 접속으로 범위를 넓히려면 네트워크·인증·암호화 전송·동시성·운영 책임을 함께 재검토해야 합니다.”

### Q12. 여러 부서가 동시에 접속하고 각자 권한을 갖고 쓸 수 있습니까?

**모범 답변**
“현재는 단일 PC·단일 관리자 중심의 운영에 맞춰져 있고, 부서별 역할 권한이나 여러 PC의 실시간 동시 편집을 제공한다고 볼 수 없습니다. 협업 운영은 사용자·역할 모델, 동시성 처리, 변경 책임, 백업·복구, 네트워크 보안을 함께 설계해야 하는 별도 단계입니다. 다른 기관에서 바로 다중 사용자 운영을 전제로 도입하는 것은 권하지 않습니다.”

### Q13. 장애나 PC 교체가 생기면 데이터를 확실히 복구할 수 있습니까?

**모범 답변**
“관리연도별 아카이브와 복원 기능은 있지만, 아카이브는 정기 백업·외부 보관·재해복구를 자동으로 보장하는 것과 다릅니다. 데이터 폴더 전체와 아카이브를 별도 위치에 보관하고, 실제로 다른 환경에서 복구되는지 정기 시험해야 합니다. 복구 시험의 성공률과 담당자 절차가 확인되기 전에는 ‘장애에도 안전하게 복구된다’고 단정하지 않겠습니다.”

**답변 포인트:** ‘아카이브 기능 존재’와 ‘검증된 백업·재해복구 체계’를 구별합니다.

### Q14. 민원 자료와 사진은 언제까지 보관하고, 어떻게 폐기합니까?

**모범 답변**
“보존기간과 폐기 시점은 각 기관의 기록관리·개인정보 처리 기준에 따라 정해야 합니다. 시스템의 아카이브·복원은 데이터 운영 기능이지 기관의 보존기간 결정을 대신하지 않습니다. 사진은 저장 용량과 개인정보 노출 측면도 있으므로 수집 필요성, 보존기간, 폐기·백업본 관리까지 기관 정책과 함께 정해야 합니다.”

**답변 포인트:** 보존기간을 임의로 제시하지 않습니다. 아카이브를 영구 보존으로 오해하게 하지 않습니다.

## 4. 확산·도입 가능성

### Q15. 다른 지자체도 그대로 가져다 쓸 수 있습니까?

**모범 답변**
“관리대장 단일 원천화, 보고 기준 명시, 자동 집계, 담당자 검수 같은 원칙은 참고할 수 있습니다. 하지만 민원 분류체계, 부서·동 코드, 보고 양식, 결재·보존 규정은 기관마다 다르므로 그대로 복사하기보다 현행 업무를 먼저 분석하고 작은 범위에서 시범 적용해야 합니다. 재사용 가능한 것은 우선 업무 원칙과 검증 방법이며, 실제 제품 적용 범위는 별도 확인이 필요합니다.”

### Q16. 기존 Excel이나 민원카드 데이터를 얼마나 쉽게 옮길 수 있습니까?

**모범 답변**
“민원카드 HWPX를 가져와 초안으로 검수한 뒤 등록하는 기능은 있습니다. 그렇다고 모든 기관의 Excel·HWPX 형식이 별도 작업 없이 자동 변환된다는 뜻은 아닙니다. 필드 매핑, 코드값 정리, 날짜 형식, 중복 판정, 사진과 첨부물 처리 기준을 표본 자료로 검증하고, 실제 자료를 옮기기 전에 건수·합계·누락을 대조해야 합니다.”

### Q17. 기존 민원 시스템이나 공통 행정 시스템과 API 연계가 가능합니까?

**모범 답변**
“현재 설명드리는 핵심 흐름은 로컬 데이터 관리와 보고 생성입니다. 특정 기관 시스템과의 운영 연계나 실시간 동기화를 이미 제공한다고 말씀드릴 근거는 없습니다. 연계를 추진한다면 데이터 소유권, 중복 입력 방지, 오류·재처리, 인증, 망 구성, 감사 책임을 먼저 정하고 기관별 승인 절차를 거쳐야 합니다.”

### Q18. 민원 건수나 사진이 늘어나도 성능 문제가 없습니까?

**모범 답변**
“사용 규모에 대한 보편적인 성능 보장을 지금 제시하기는 어렵습니다. 특히 사진은 데이터베이스 용량과 백업·복구 시간에 영향을 줄 수 있어 압축, 크기 제한과 저장량 관리를 고려하고 있습니다. 적용 전에는 기관의 예상 건수·사진량·보존기간으로 부하와 복구 시험을 해야 하며, 특정 규모까지 문제없다고 말하려면 그 조건에서의 시험 결과가 필요합니다.”

### Q19. 도입 비용과 운영 인력은 어느 정도 필요합니까?

**모범 답변**
“기관의 분류체계 정비, 기존 자료 이관, 보안 검토, 배포·교육, 백업·복구 책임을 포함한 총비용을 산정한 자료가 확인되지 않는 한 비용이나 인력 절감 효과를 단정하지 않겠습니다. 도입 검토에서는 소프트웨어 비용만이 아니라 데이터 정비, 담당자 교육, 업데이트, 장애 대응과 복구 시험에 필요한 내부 시간을 함께 계산해야 합니다.”

### Q20. 누가 잘못된 집계나 개인정보 유출에 책임집니까?

**모범 답변**
“시스템이 집계와 기록을 지원하더라도 업무 데이터의 정확성, 보고 승인, 개인정보 반출과 계정 관리에 대한 기관의 책임을 대신하지 않습니다. 담당자·검토자·관리자의 역할과 다운로드 승인, 오류 정정, 사고 대응 절차를 기관 운영 규정에 맞게 정해야 합니다. 제품 기능과 행정적 책임을 구분하는 것이 전제입니다.”
