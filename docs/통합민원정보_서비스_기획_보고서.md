## 1. 보고 요지

통합민원정보는 생활민원 자료를 **관리대장 한곳**에 입력·정리하면, 부서별 현황·총괄표·일일보고·대시보드와 Excel 보고서가 **동일한 숫자**로 자동 반영되는 업무 지원 서비스입니다. Windows PC에서 별도 설치 부담 없이 사용할 수 있도록 포터블 형태로 배포합니다.

**추진 방향**

> 입력은 한 번, 집계는 일관되게, 보고는 검증 가능하게, 데이터는 안전하게.

**현재까지의 성과**

- 여러 Excel 시트를 손으로 맞추던 방식에서 벗어나, 관리대장 기준으로 보고서를 일괄 산출합니다.
- 보고일을 선택하고, 확정 시점의 보고 결과를 보존하며, 전일·전주 대비 접수·처리중 증감율을 확인할 수 있습니다.
- 민원인 성명·연락처·사진 등은 저장 시 암호화하고, 화면에서는 기본 마스킹을 적용합니다. 필요 시 2단계 인증을 켤 수 있습니다.
- 한글 민원카드(HWPX)를 가져와 초안으로 검수한 뒤 등록할 수 있어 재입력 부담을 줄입니다.

**남은 핵심 과제**

1. 통합 Excel 내려받기 시 개인정보 **기본 마스킹**과 원문 포함 시 **확인·이력 기록**
2. PC 교체·장애에 대비한 **백업·복구 절차의 정형화**
3. 보고 숫자 오류를 예방하기 위한 **집계 규칙 검증 강화**

위 과제가 마무리되면, 단순 Excel 대체 도구를 넘어 **반복·검증 가능한 민원 보고 업무 체계**로 운영할 수 있습니다.

## 2. 추진 배경

### 2.1 업무 현황

생활민원 담당자는 접수 자료를 관리대장에 기록하고, 처리 부서와 상태를 갱신한 뒤 같은 내용을 부서별 현황·총괄표·일일보고 등 여러 양식으로 다시 정리해 왔습니다. 기존에는 Excel 시트 간 수식과 파일 복사에 크게 의존했습니다.

### 2.2 개선이 필요했던 점

| 구분 | 업무상 어려움 | 서비스로 개선한 점 |
|---|---|---|
| 보고 작성 | 시트마다 숫자가 달라지고 원인 추적이 어려움 | 관리대장만 수정하면 나머지 보고서는 자동 집계 |
| 일일보고 | 통보일·보고일을 잘못 적용할 위험 | 보고일 기준 경로·분야 집계 자동화 |
| 자료 입력 | 민원카드·사진 재입력으로 시간 소요·누락 | HWPX 가져오기 후 검수·등록 |
| 실행 환경 | PC마다 설치·환경이 달라 운영 비용 발생 | Windows 포터블 배포 |
| 개인정보 | 화면·파일 공유 과정에서 과다 노출 우려 | 화면 마스킹, 저장 암호화, (선택) 2단계 인증 |
| 사후 검증 | 당시 보고 숫자를 나중에 재확인하기 어려움 | 보고 확정(스냅샷)으로 결과 보존 |

## 3. 서비스 개요

### 3.1 목표

1. 민원 한 건을 한 번 입력하거나 가져오면 모든 현황 화면과 보고서에 일관되게 반영한다.
2. 통보일·보고일·처리 상태를 화면에 명확히 구분해 보고 기준 오류를 줄인다.
3. 민원카드 원본을 보관하지 않고도 핵심 정보와 사진을 빠르게 등록한다.
4. Excel 생성·검토·공유 과정에서 개인정보 노출을 통제하고 이력을 남긴다.
5. 포터블 운영을 유지하면서 백업·복구와 버전 업데이트를 쉽게 한다.
6. 향후 여러 담당자가 함께 쓰는 환경으로 확장할 수 있도록 기반을 정리한다.

### 3.2 현 단계에서의 범위 밖

클라우드 공동 이용, 모바일 전용 앱, 외부 민원 접수 채널 직접 연계, 복잡한 조직별 권한 체계, 여러 PC에서의 실시간 동시 편집은 이번 단계의 목표에 포함하지 않습니다. 단일 PC 운영이 안정된 뒤 별도로 검토합니다.

### 3.3 이용 역할

| 역할 | 주요 과업 | 성공의 기준 |
|---|---|---|
| 민원 담당자 | 자료 가져오기·보완, 기간별 현황 확인 | 입력 시간 단축, 재작업 감소 |
| 보고 작성자 | 보고일 설정, 보고 확정, Excel 작성 | 숫자 재현, 기준일 명확 |
| 관리자 | 비밀번호·보안 설정, 이력 확인, 데이터 관리 | 변경 추적, 복구 가능 |
| 검토자·상급자 | 대시보드·보고서 확인 | 미처리 우선순위와 핵심 현황 파악 |

현재는 단일 관리자 계정 중심이며, 위 구분은 업무 역할입니다. 계정·권한 분리는 이후 단계에서 도입합니다.

### 3.4 화면 구성

| 메뉴 | 역할 |
|---|---|
| 대시보드 | 전체 현황, 미처리 우선순위, 증감율, 통합 Excel |
| 관리대장 | 민원 등록·수정·삭제 (유일한 입력 원천) |
| 부서별현황 | 부서별 건수·완료·미처리·처리율 |
| 총괄표 | 처리 개요, 기간·경로·분야·실국 요약 |
| 일일보고 | 보고일 기준 경로×분야·동별 집계 |
| 보고 확정 | 보고일 기준 결과 보존 및 이력 조회 |
| 감사로그 | 로그인·민원·설정 변경 이력 |
| 설정 | 비밀번호, 2단계 인증, 데이터 보호 상태 등 |

**운영 원칙:** 관리대장만 수정하고, 나머지 보고서는 조회 시점에 집계합니다. 확정이 필요한 보고는 스냅샷으로 남겨 이후 원천 데이터가 바뀌어도 당시 숫자를 유지합니다.

## 5. 향후 추진 계획

### 5.1 전략

1. **보고의 신뢰성을 최우선으로 유지한다.**  
   기준일·대상 건수·확정본으로 “이 숫자가 어떤 기준으로 나왔는지”를 설명할 수 있게 한다.
2. **로컬 운영은 유지하되, 데이터 이전·복구를 제품 기능으로 만든다.**  
   담당 PC 교체나 장애 시에도 업무 연속성을 확보한다.
3. **개인정보 보호를 파일 공유 단계까지 완성한다.**  
   저장·화면 보호에 더해, Excel 내려받기 기본값을 안전하게 맞춘다.

### 5.2 단계별 계획

| 단계 | 목표 | 주요 내용 | 상태 |
|---|---|---|---|
| 1단계 | 보고 신뢰성 기반 | 보고일·기준 표시, 확정·증감율 | 완료 |
| 2단계 | 공유·운영 안정화 | Excel 기본 마스킹·내려받기 이력, 백업·복구, 검증 강화 | **진행 예정** |
| 3단계 | 협업 운영 | 사용자·역할, 사내망 공동 이용, 부서별 처리 요청 등 | 이후 검토 |

### 5.3 즉시 추진 과제

| 순서 | 과제 | 기대 효과 | 완료 기준 |
|---:|---|---|---|
| 1 | 통합 Excel 기본 마스킹 | 공유 시 개인정보 과다 노출 방지 | 원문 미선택 시 성명·연락처 등이 가려진 채로 생성 |
| 2 | 내려받기 이력 기록 | 책임 추적·점검 가능 | 감사로그에서 조건·시각·담당 확인 |
| 3 | 백업·복구 절차 정비 | PC 교체·장애 시 업무 연속 | 별도 PC 또는 폴더에서 복구 점검 성공 |
| 4 | 집계·확정 규칙 검증 | 보고 오류 조기 발견 | 주요 사례 자동 검증 |
| 5 | 사진 용량 관리 | 성능·오류 예방 | 대용량 등록 시 안내·제한 |

### 5.4 운영 성과 지표 (안)

| 지표 | 방향 |
|---|---|
| 신규 민원 등록에 걸리는 시간 | HWPX 활용 시 수동 입력 대비 단축 |
| 보고서 생성 성공률 | 오류 없이 생성되는 비율을 높게 유지 |
| 보고 기준 오류율 | 보고일·기간 수정이 필요한 경우 지속 감소 |
| 확정 보고 재현율 | 같은 확정본 조회 시 결과 일치 |
| 백업 복구 성공률 | 정기 점검에서 성공 |
| 원문(비마스킹) 내려받기 비율 | 업무상 꼭 필요한 경우만 발생하도록 관리 |

지표 수집 과정에서 개인정보를 추가로 저장하지 않도록 합니다.

## 6. 운영·보안 원칙

1. 실제 운영 자료와 샘플·연습 자료를 분리한다.
2. 실제 민원 데이터베이스와 원본 자료는 외부 저장소·메신저로 공유하지 않는다.
3. 기본 접속은 해당 PC 내부(로컬)로 두고, 외부 접속이 필요하면 보안 대책을 함께 검토한다.
4. 비밀번호 변경, 데이터 초기화, 원문 Excel 내려받기는 높은 주의가 필요한 작업으로 다룬다.
5. 민원카드(HWPX)는 가져오기 후 원본을 서비스에 보관하지 않는다.
6. 화면에서 가리기(마스킹)와 저장 암호화는 목적이 다르며, 둘 다 유지한다.
7. 백업은 파일 복사에서 끝내지 않고, 복구 확인까지 포함한다.
8. 비밀번호를 분실하면 암호화된 개인정보는 복구할 수 없음을 사용자에게 고지한다.

## 7. 결론 및 제언

통합민원정보는 기존 Excel 중심 업무의 핵심 문제였던 **보고서 간 숫자 불일치**와 **PC별 실행 환경 의존**을 해소하는 방향으로 구축되어 있습니다. 보고일 지정, 보고 확정, 증감율 확인, 개인정보 저장 보호까지 반영되어 현장 보고 업무에 바로 활용할 수 있는 수준에 이르렀습니다.

다만 완성도를 높이기 위한 다음 단계는 기능을 더 늘리는 일이 아니라, 아래 세 가지를 마무리하는 일입니다.

1. **통합 Excel의 기본 마스킹과 내려받기 이력**으로 공유 단계의 개인정보 통제를 완성한다.  
2. **백업·복구 절차를 정형화**하여 단일 PC 운영의 지속 가능성을 확보한다.  
3. **집계·확정 규칙을 검증**하여 보고 신뢰성을 유지한다.

위 과제가 정리되면 서비스는 Excel 대체 수단을 넘어, 전주시 생활민원 보고를 안정적으로 지원하는 업무 시스템으로 자리잡을 수 있습니다. 여러 담당자 공동 이용과 사내망 확장은 그 이후 단계에서 검토할 것을 제안합니다.
